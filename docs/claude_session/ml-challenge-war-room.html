Business Entity Resolution

Given business records from three noisy sources with no shared identifiers, decide which records refer to the same real-world business. Source 1 is the clean reference; for every Source 1 entity, find its matches in Source 2 and Source 3 — which may be zero, one, or many.

The task, precisely

What is scored

Input. Three tab-separated files per split. Every record has entity_id (prefixed S1- / S2- / S3-), business_name, business_address, country. Read with sep="\t" — without it pandas silently gives you one column.

Output. One row per test Source 1 entity, with a comma-separated list of matched S2/S3 IDs, empty when there are none. Plus a second file, candidate_pairs.tsv, holding the candidate set your blocking stage fed to the model.

The noise is the problem. Names carry abbreviations (Corp/Corporation, Pvt/Private), legal-suffix mismatches, DBA names, & vs "and", transposed words, typos. Addresses carry Rd/Road, transliterations, missing PIN codes, landmark references ("Near SBI ATM"), reordered components.

The trap. Training covers US and India. The test set adds France, which never appears in training. Nothing may be hard-coded, filtered or one-hot encoded to {US, India}, and every test entity including the French ones must appear in the submission.

The metric decides the strategy

F0.5, macro-averaged
F_0.5 = (1.25 x P x R) / (0.25 x P + R)

Computed per Source 1 entity, then averaged. So every entity counts the same whether it has ten matches or none — and precision is weighted twice as heavily as recall.

Singletons are free marks. An entity with no true matches scores a full 1.0 if you correctly output an empty list, and 0.0 if you predict anything at all. Guessing on an uncertain entity is not a cheap lottery ticket — it can cost a whole point.

The decision rule that falls out of this: for an entity where you have one candidate, predict it only when you believe it is a true match more strongly than you believe the entity is a singleton. Otherwise output nothing.

SituationYou predictScore
1 true matchexactly it1.00
1 true matchit + 1 wrong0.56
1 true matchnothing0.00
No true matchnothing1.00
No true matchanything0.00

Read the middle rows together: adding a wrong ID next to a right one costs about 0.44, but firing on a singleton costs the full 1.00. When in doubt, stay silent.

The pipeline

Five stages, four owners
1
Owner A · hour 0–4

Normalise, and build the scoring harness

Unicode-fold, lowercase, strip punctuation, expand the abbreviation table both ways (corp→corporation, rd→road, pvt→private). Pull numeric tokens — street numbers, PIN codes — into their own fields. Then implement F0.5 macro exactly as specified and hold out a split of Source 1 entities. Everything the team quotes for three days comes out of this function.

2
Owner B · hour 4–16

Blocking / candidate generation

Character n-gram TF-IDF over name (and address), sparse cosine, top-k neighbours per S1 entity. This sets the ceiling on recall — a true match not in your candidate set can never be recovered downstream. Measure two numbers and keep measuring them: recall of the candidate set, and reduction ratio. Aim high on recall, generous k; precision is the model's job, not blocking's.

3
Owner C · hour 8–30

Pairwise features

Per candidate pair: TF-IDF cosine on name and on address, token Jaccard, Jaro-Winkler and Levenshtein ratio, IDF-weighted rare-token overlap (a shared rare word means far more than a shared "restaurant"), numeric-token exact match, length ratios, same-country flag, and counts of each side's tokens. Rare-token overlap and numeric match are usually the two strongest features in this kind of task.

4
Owner B + C · hour 20–44

Pairwise classifier

Gradient boosting (LightGBM / XGBoost) over those features. Positives come from the ground truth; negatives are the hard ones — candidates your blocking produced that are not true matches. Random negatives teach the model nothing. Optionally add a small open-licence sentence embedding for semantic name similarity; check it is MIT/Apache and under 8B before it goes anywhere near the final pipeline.

5
Team lead · hour 30–68

Thresholding — where the score actually comes from

Sweep the decision threshold against F0.5 on the held-out split, and treat "output empty" as a real prediction rather than a fallback. Expect the optimum to sit well above 0.5. This one sweep is usually worth more than another model.

The France test

Generalisation check

The test set contains a country the training data has never seen, so a model that has quietly learned "US addresses look like this, Indian ones like that" will fall over on a third of the private leaderboard.

Cheap way to catch it: train on US records only, validate on India only. If the score collapses, the pipeline is country-dependent and needs fixing before day 3 — not discovered after the private leaderboard opens.

Practical consequences: no country-specific regexes as hard rules, no one-hot over the observed country set, and keep character-level features that work on any script.

Red lines — instant disqualification

  • No external lookup of business identities. No commercial entity-resolution APIs, no government business registries, no geocoding APIs for address normalisation, no internet data augmentation of any kind. Code pipelines are reviewed.
  • Final model must be MIT or Apache 2.0 licensed and at most 8B parameters. Check the licence before adding any pretrained model.
  • Multiple accounts or IDs; one person on more than one team; sharing code or predictions between teams.
  • Simultaneous logins for the same participant.

Everything built from the provided training data is fair game: any library, feature engineering, gradient boosting, open-licence embeddings within the cap.

Working together without friction

Cheap habits, large payoff

Set up in the first hour

  • One shared repo or drive: data/, src/, outputs/, doc/ — matching the required zip layout from the start.
  • One experiment sheet: who, what changed, candidate recall, local F0.5, public score, file name. Unlogged runs do not exist.
  • File naming: sub_03_lgbm_thr0.72_f0.641.tsv — score in the name, so nobody has to ask.
  • One voice channel open and muted all three days.

Rules that prevent the usual fights

  • The leader alone uploads — and is the only one who can, per the portal rules.
  • Nobody changes the validation split after hour 6. If it changes, every past number is void.
  • Sleep in shifts. Two sharp people beat four exhausted ones at hour 60.
  • Disagreements go to the split, not to argument. Run both, compare F0.5, move on.
  • Say "I'm stuck" at 30 minutes, not at three hours.
